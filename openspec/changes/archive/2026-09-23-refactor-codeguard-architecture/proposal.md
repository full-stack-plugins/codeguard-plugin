# Proposal

## Why

CodeGuard 的能力方向成立，但入口、执行、判定、存储、报告互相穿透，修复同类缺陷时需要修改多个入口。以 `61e2592`（v0.12.1）为行为基线，在保留已有全部能力、协议和配置的前提下建立可测试的模块边界；不是换语言、堆抽象类或仅搬动文件。

## What Changes

- 建立标准 Python 包内核：纯判定模型、统一进程执行、检查编排、基础设施与入口适配分离。
- CLI、MCP、五个 hook 保持原路径和协议，逐步成为薄适配层；旧 Python 导入接口作为明确兼容面保留。
- 合并重复的进程执行与故障归一化，保留真实退出码、命令、输出和未验证原因；超时仍保留已产生的诊断。
- 分离 Git 意图解析/快照、安全规则、缓存、审计与报告，消除不可达分支和重复副作用，保持门禁策略不变。
- 整理配置、注册表、Java 项目分析及 CVE 适配器的责任边界，统一依赖方向，不改变受管技能内容。
- 建立兼容性场景清单、真实进程和 Git 契约测试、架构依赖门禁、能力追溯与发布验收。
- 更新开发指南、架构图和验证边界；旧历史报告保留历史身份，不把计划写成完成证明。

## Capabilities

### New Capabilities

- `execution-kernel`：统一进程证据契约、故障归一化与调用方无关的执行边界。

### Modified Capabilities

无。既有 verdict-integrity、hook-protocol、language-gate-commands、MCP、Java、CVE 契约均作为必须保留的行为约束。其他未归档 change 的已交付行为也纳入基线，不覆盖其 tasks 或擅自归档。

## Impact

影响 `scripts/`、`hooks/`、`tests/`、开发文档和 CI；完成后按仓库规定升级版本、发布并同步市场。保持 57 个语言注册项、68 个受管技能、四个 MCP 工具、五类 hook、全部现有 CLI 子命令与默认检查等级。无需安装新运行时依赖，不初始化 SDD，不迁移规格体系，不更改用户项目或宿主配置。

CodeGraph 在目标仓尚未初始化，已请求用户批准；在批准前源码证据有效但不标为图谱证据。不得将已有 275 测试中的 4 项 skip 当作已验收；三宿主运行、真实工具链与线上漏洞数据另列证据。
